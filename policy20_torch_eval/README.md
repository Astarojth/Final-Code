# policy20_torch_eval

This directory contains a true manual autoregressive decoder for Qwen-style
thinking models. It uses Hugging Face/PyTorch directly, keeps the KV cache
alive across token steps, exposes logits every step, and applies policy20
decisions without repeated vLLM prefill calls.

The script intentionally reuses the existing online-eval dataset loaders,
StageAB-aligned evaluators, and policy artifact loaders. The generation loop is
independent from vLLM.

Example:

```bash
python3 policy20_torch_eval/torch_online_eval.py \
  --config policy20_torch_eval/config.qwen3_4b_thinking_2507.torch.local.yaml \
  --output-dir /path/to/policy20_torch_eval \
  --baselines segmented_global_best_no_switch dynamic_global_best_start \
  --datasets gsm8k mbpp \
  --max-items-per-dataset 10
```

Supported baseline names:

- `segmented_global_best_no_switch`: torch manual decode, global best start, no switch.
- `segmented_category_best_no_switch`: torch manual decode, category best start, no switch.
- `dynamic_global_best_start`: torch manual decode, global best start, policy switches enabled.
- `dynamic_category_best_start`: torch manual decode, category best start, policy switches enabled.

The output token count is completion tokens generated by the manual loop. It
also writes separate `think_token_count` and `answer_token_count` estimates.

Useful optional config under `policy_runtime`:

```yaml
policy_runtime:
  boundary_min_tokens: 6
  reasoning_end_control: force      # force | bias_close
  reasoning_end_token_bias: 100.0   # used by bias_close
```

`torch_max_total_tokens` is optional and normally unnecessary. If omitted, the
script uses the same budget shape as the current eval config:
`max(cot_budgets) + static_answer_completion_budget`, capped by
`model.max_model_len - prompt_tokens`.
